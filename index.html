Inheritance in Java

A Real-Life Scenario

Lesson 1 of 3

The Problem: Duplicate Attributes

Imagine a library system — like the one at Singapore Polytechnic — that serves two types of members: students and staff. To keep track of these members in a Java program, the most straightforward approach is to create one class for Student and a separate class for Staff.

Each of these classes needs to store roughly the same information: a name, an ID, a department, and a borrowing quota — along with a few methods to work with that data, such as setting the basic details or reading back the quota.

Here's the problem: once you write both classes out, they end up looking almost identical. Most of their attributes (name, ID, department, quota) and their methods (setBasics(), setQuota(), getQuota()) are exactly the same in both classes. Only a couple of details differ — students have a studentClass, staff have a designation. Writing the same characteristics twice works, but it's repetitive, and it gets harder to keep in sync as the program grows.

Key Takeaways
  • Two related classes (Student, Staff) can end up sharing almost all of the same attributes and methods.
  • Duplicating that shared code in each class works, but it's inefficient and risky to maintain.
  • Only a small part of each class is actually unique to it.

Lesson 2 of 3

The Solution: A Shared Superclass

Rather than repeating the same characteristics in both classes, we can pull everything Student and Staff have in common out into one shared class, called a superclass (also called a parent class).

In this example, that shared class is Member. It holds the attributes every member has in common — name, ID, department, and quota — along with the methods that work with them: setBasics(), setQuota(), and getQuota().

Student and Staff are then defined as subclasses (or child classes) of Member. Each subclass only needs to add whatever makes it different: Student adds a studentClass attribute, and Staff adds a designation attribute. This relationship — a general superclass with more specific subclasses branching off it — is what's called inheritance in object-oriented programming.

Key Takeaways
  • A superclass (parent class) holds the attributes and methods that multiple classes share.
  • A subclass (child class) is built on top of a superclass and only defines what's unique to it.
  • Member is the superclass here; Student and Staff are its subclasses.

Lesson 3 of 3

Inheritance in Action

Once Student and Staff are defined as subclasses of Member, something convenient happens automatically: they inherit every attribute and method defined in Member, without needing to redeclare any of it.

That means a Student object automatically has a name, ID, department, and quota, and can use setBasics(), setQuota(), and getQuota() — even though none of that code was written directly inside the Student class. The same is true for Staff.

On top of what they inherit, each subclass can still define its own unique characteristics: Student keeps its own studentClass attribute, and Staff keeps its own designation attribute. This is the payoff of the design — shared behavior is written once, in the superclass, and reused everywhere it's needed, while each subclass stays free to add whatever makes it distinct.

Key Takeaways
  • Subclasses automatically inherit every attribute and method from their superclass.
  • Inherited characteristics don't need to be rewritten in the subclass.
  • Subclasses can still add their own unique attributes and methods alongside what they inherit.
